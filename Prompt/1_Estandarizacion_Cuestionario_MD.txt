# 10. DETERMINACIÓN DEL TIPO
Aplica esta precedencia:

## 10.1 GRID con varias variables
Usa `GRID con varias variables` cuando un padre contenga dos o más campos de captura independientes, incluidas fechas divididas, matrices con varias columnas y baterías con subpreguntas.

## 10.2 Categorico Respuesta Multiple
Úsalo cuando aparezca RM, se permita elegir varias opciones o exista una cardinalidad máxima mayor que uno.

## 10.3 Categorico Respuesta Unica
Úsalo cuando aparezca RU, exista una lista de selección única o el contexto documente una única respuesta.

## 10.4 Fecha
Úsalo cuando una variable capture una fecha completa sin subcampos.

## 10.5 Decimal
Úsalo para montos o mediciones que admitan decimales explícitamente.

## 10.6 Numerica
Úsalo para enteros abiertos, edades, cantidades, conteos, años y mediciones enteras. Una lista con códigos numéricos sigue siendo categórica.

## 10.7 Texto
Úsalo para respuestas abiertas textuales, nombres, teléfonos, documentos, correos, comentarios y especificaciones abiertas.

## 10.8 Informacion
Úsalo cuando el cuestionario declare un elemento informativo o cuando una introducción forme parte funcional del flujo y deba preservarse en Metadata conforme a la sección 28. No conviertas títulos decorativos o notas ajenas al flujo en variables de información.

## 10.9 Otro
Úsalo únicamente cuando la evidencia no permita asignar otro tipo.

# 11. CARDINALIDAD
Incluye `Cardinalidad` en toda variable o subcampo categórico cuando sea explícita o pueda determinarse directamente por RU/RM y límites documentados.

Escribe exclusivamente una de estas formas:
- `1..1`
- `1..`
- `0..1`
- `0..`
- `MIN..MAX`
- `MIN..`

Reglas:
- RU implica `1..1`, salvo que el documento indique explícitamente que puede quedar sin respuesta, en cuyo caso usa `0..1`.
- RM sin límites explícitos implica `1..`.
- “Seleccione máximo 3” implica `1..3`.
- “Seleccione al menos 2” implica `2..`.
- “Seleccione entre 2 y 5” implica `2..5`.
- Usa mínimo cero solo si se indica explícitamente que puede omitirse la respuesta.
- No inventes máximos ni mínimos.
- Conserva la cardinalidad en el padre o subcampo exacto al que aplica.

# 12. RANGOS Y VALIDACIONES LITERALES
## 12.1 Rango
Incluye `Rango` solo ante un mínimo y máximo inequívocos o un límite literal aplicable a una variable numérica, decimal o textual.

Formatos:
- `MIN..MAX`
- `MIN..`
- `..MAX`

Ejemplos documentales:
- “RANGO DE 0 A 60” → `Rango: 0..60`
- “PERMITIR AÑOS DE 1946 A 2007” → `Rango: 1946..2007`
- “MÁXIMO 200 CARACTERES” → `Rango: 0..200`

No deduzcas rangos desde categorías, ejemplos o conocimiento externo.

## 12.2 Validación literal
Incluye `Validación literal` únicamente cuando el cuestionario proporcione una expresión regular literal o una regla exacta de formato que deba preservarse textualmente.

No inventes regex. Conserva literalmente la expresión o regla después de limpiar solo el prefijo técnico redundante.

# 13. ROTACIÓN, ALEATORIZACIÓN Y ORDEN
No elimines estas instrucciones. Regístralas en el campo `Rotación` de la variable, subcampo o conjunto exacto al que apliquen.

Mapeo:
- ROTAR o ROTANDO → `ROTAR`
- RANDOMIZAR, ALEATORIZAR o ALEATORIAMENTE → `RANDOMIZAR`
- ALFABÉTICO A-Z → `ALFABÉTICO A-Z`
- ALFABÉTICO Z-A → `ALFABÉTICO Z-A`
- INVERTIDO → `INVERTIDO`

Si la instrucción aplica solo a algunas alternativas, registra además `Fija = Sí` en las alternativas expresamente excluidas del universo de rotación.

No conviertas rotación en una indicación genérica ni la incorpores a la etiqueta.

# 14. CATEGORÍAS Y ATRIBUTOS ESPECIALES
Cuando existan opciones, usa una tabla Markdown con estas columnas exactas:

`| Código | Etiqueta | Exclusiva | Fija | Especificar | Tipo captura | Rango captura |`

Cabecera:
`|---|---|---|---|---|---|---|`

Reglas:
- Cada opción ocupa una fila.
- Conserva el orden documental original. El conversor MDD realizará el reordenamiento técnico.
- Conserva códigos literalmente, incluidos ceros iniciales.
- Si no hay código, deja la celda vacía. No lo inventes.
- Conserva la etiqueta visible después de retirar únicamente las marcas técnicas trasladadas a columnas propias.
- Conserva números entre paréntesis que formen parte real de la etiqueta de respuesta, por ejemplo `(1)`, `(2)` o referencias textuales. No los elimines ni los interpretes como código salvo que la estructura del cuestionario demuestre inequívocamente que son códigos técnicos.
- Escapa `|` dentro de una celda como `\|`.
- No generes tablas vacías ni HTML.
- No deduzcas exclusividad por código o wording. Marca solo la exclusividad explícita del cuestionario; el conversor aplicará además sus reglas semánticas y técnicas.
- No deduzcas fijación por código. Marca solo `FIJAR`, `FIJA`, “NO ROTAR”, exclusión explícita de rotación o equivalente inequívoco.

## 14.1 Exclusiva
Si la opción está marcada como EXCLUSIVA o equivalente inequívoco, escribe `Sí` en `Exclusiva`.

## 14.2 Fija
Si está marcada como FIJAR, FIJA, NO ROTAR o está expresamente fuera de la rotación, escribe `Sí` en `Fija`.

## 14.3 Especificar y captura asociada
Escribe `Sí` en `Especificar` únicamente cuando exista una solicitud inequívoca de especificación o un campo abierto asociado a esa categoría.

La palabra “Otro”, “Otra” u “Otros” por sí sola no basta.

En `Tipo captura`, usa uno de:
- `Texto`
- `Numerica`
- `Decimal`
- `Fecha`
- `Otro`

En `Rango captura`, usa el rango explícito con formato `MIN..MAX`, `MIN..` o `..MAX`. Déjalo vacío si no existe.

Ejemplo estructural:
`| 94 | Otro, especifique |  | Sí | Sí | Texto | 0..200 |`

# 15. CAPTURAS ASOCIADAS SIN CATEGORÍA

# 16. INDICACIONES OPERATIVAS
Conserva en `Indicaciones` únicamente información que el Markdown deba documentar para trazabilidad y que no tenga un campo específico anterior:
- continuación;
- terminación;
- detención de grabación;
- selección requerida;
- exclusión entre preguntas;
- piping o presentación de respuestas previas;
- BACKCHECK.

No repitas aquí tipo, cardinalidad, rango, validación, rotación, exclusividad, fijación o captura asociada.

Elimina solo el prefijo `PROG:` y reformula únicamente cuando exista un mapeo inequívoco:
- `CONTINUAR` asociado al código 1 → `Continuar si marca codigo 1`.
- `AGRADEZCA Y TERMINE` asociado al código 2 → `Terminar si marca codigo 2`.
- `DETENER LA GRABACIÓN Y CONTINÚE` asociado al código 2 → `Detener la grabacion si marca codigo 2 y continuar`.
- `TERMINAR F8=COD 3` → `TERMINAR SI SELECCIONA COD 3`.
- `TERMINAR SI NO SELECCIONA F5=COD 2` → `TERMINAR SI NO SELECCIONA COD 2`.
- `SI ES MENOR DE 18 AÑOS AGRADEZCA Y TERMINE` → `TERMINAR SI ES MENOR DE 18 AÑOS`.

Para otras instrucciones conserva el contenido y significado, sin agregar condiciones.

Una regla usa `Indicaciones`; varias usan `Indicaciones1`, `Indicaciones2`, etc., en orden documental, sin duplicados.

# 17. ASIGNACIÓN DE INSTRUCCIONES
1. Si menciona una variable destino, asígnala a esa variable.
2. Si condiciona la respuesta anterior, asígnala a la anterior.
3. Si afecta varias variables, asígnala a la última variable del bloque, salvo que el documento individualice destinos.
4. Si no existe destino claro, asígnala a la variable inmediatamente anterior.
5. No dupliques instrucciones conjuntas.
6. Cardinalidad, rango, validación, rotación y atributos de categoría se asignan siempre al elemento exacto al que visual o textualmente correspondan.

# 18. LISTAS COMUNES Y TABLAS COMPARTIDAS

Cuando dos o más preguntas reutilicen exactamente el mismo conjunto de opciones, códigos, orden, cardinalidad y atributos, asegúrate de que la representación Markdown sea idéntica; no omitas opciones en una de las apariciones. Esta normalización permite que Easy Script 2 cree una lista reutilizable `define/use` de forma segura.

Cuando una tabla contenga categorías para dos o más variables independientes, crea una variable por cada columna de captura, con etiqueta, tipo, cardinalidad, atributos y tabla propios. Conserva el orden de las columnas.

No combines variables independientes en un padre salvo que el cuestionario documente una estructura padre/subcampo.

Para matrices homogéneas, representa las filas como `Categorías` del padre cuando sean los elementos iterados, y las opciones de respuesta como `Categorías` del subcampo común. Si el documento presenta subpreguntas con identificadores propios, conserva cada una como subcampo.
