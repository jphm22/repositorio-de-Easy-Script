# 11. SELECCIÓN DEL EVENTO

Elige el evento por el momento funcional, no por costumbre.

- `onEntrance`: inicialización operativa al entrar; inicio de backcheck/grabación cuando esté corroborado.
- `onInputChange`: cálculos/feedback que deben actualizarse durante la respuesta.
- `onNext`: recodes posteriores a captura; routing/terminación; validaciones de salida; parada de grabación; asignaciones que dependen de la respuesta recién capturada.
- función custom: validación específica asociada por el mecanismo OSM correspondiente.

No uses `onBeforeNavigateTo` indiscriminadamente para toda asignación. Úsalo cuando el estado deba estar listo antes de mostrar el nodo.

CASO 3. BACKCHECK CON GRABACIÓN SILENCIOSA

Situación:
El estudio requiere que el proceso de BACKCHECK active una grabación de audio silenciosa al ingresar a una pregunta específica y la detenga al finalizar dicha sección.

Patrón de implementación:

OSM.Survey.S5.addEventListener('onEntrance', function(e) {
    var chainId = OSM.Survey.SHELL_CHAINID.getComment();
    OSM.Survey.startSilentAudioRecording(chainId + '_(S5)');
});

OSM.Survey.S5.addEventListener('onNext', function(e) {
    OSM.Survey.stopSilentAudioRecording();
});

Consideraciones:
- Utilizar el identificador del entrevistado (SHELL_CHAINID) para generar el nombre de la grabación.
- Iniciar la grabación al entrar en la pregunta objetivo.
- Detener la grabación al abandonar la pregunta.
- No asumir que todos los proyectos con BACKCHECK utilizan este comportamiento. Verificar siempre los requerimientos específicos del estudio antes de aplicar este patrón.

CASO 4. F21 A F22: CARRY-FORWARD MEDIANTE FILTRADO DE ITERACIONES

Situación:
La pregunta F21 registra múltiples formas de consumo mediante una variable de respuesta múltiple (RM). Posteriormente, F22 solicita una frecuencia para cada una de las opciones seleccionadas en F21.

Estructura MDD:
- F21: Variable categórica de respuesta múltiple.
- F22: Loop basado en las categorías de F21.
- Cada iteración de F22 contiene una pregunta de respuesta única (RU).

Implementación:

OSM.Survey.F22.addEventListener('onBeforeNavigateTo', function(e) {
    e.sourceElement.filterIterations(OSM.Survey.F21.getAnswers());
});

Consideraciones:
- El filtrado debe realizarse antes de mostrar el loop.
- Solo se presentan las iteraciones correspondientes a las respuestas seleccionadas en F21.
- El universo completo de categorías debe mantenerse definido en el MDD.
- El script únicamente controla cuáles iteraciones permanecen activas durante la ejecución.

CASO 5. VALIDACIÓN DE EDAD Y GÉNERO CONTRA VARIABLES SHELL

Situación:
Cuando la información demográfica ya existe en variables SHELL, esta debe utilizarse como fuente oficial para validar filtros, cuotas y consistencia de respuestas.

Validación de edad utilizando SHELL_AGE:

El siguiente patrón:
- Obtiene la edad desde SHELL_AGE.
- Actualiza las variables de trabajo.
- Aplica los filtros de elegibilidad.
- Asigna el rango etario correspondiente.
- Actualiza la cuota de edad.

OSM.Survey.SHELL_AGE.addEventListener('onNext', function(e) {
    if (e.sourceElement.isAnswerSelected('_A1')) {
        var edad = parseInt(e.sourceElement._A1.getComment());

        s.AGE.setComment(edad);

        if (edad < 18) {
            OSM.Survey.ELIMI.setComment(
                e.sourceElement.get('objectName') +
                '. No cumple filtro de edad. Agradecer y terminar encuesta.'
            );
            OSM.Survey.get('navigator').goTo(OSM.Survey.ELIMI);
        } else {
            if (edad >= 18 && edad <= 24) {
                s.AGE_R.setAnswers('_2');
            }
            if (edad >= 25 && edad <= 35) {
                s.AGE_R.setAnswers('_3');
            }
            if (edad >= 36 && edad <= 45) {
                s.AGE_R.setAnswers('_4');
            }
            if (edad >= 46 && edad <= 55) {
                s.AGE_R.setAnswers('_5');
            }
            if (edad >= 56) {
                s.AGE_R.setAnswers('_6');
            }

            s.CUOTA_EDAD.setAnswers(s.AGE_R.getAnswers());
        }
    } else {
        s.ELIMI.setComment(
            e.sourceElement.get('objectName') +
            '. Rehúsa brindar su edad. Terminar encuesta.'
        );
        s.get('navigator').goTo(s.ELIMI);
    }
});

Validación de género utilizando SHELL_GENDER:

OSM.Survey.SHELL_GENDER.addEventListener('onNext', function(e) {
    if (OSM.Survey.SHELL_GENDER.isAnswerSelected('_A1')) {
        OSM.Survey.F4.setAnswers('_1');
    }

    if (OSM.Survey.SHELL_GENDER.isAnswerSelected('_A2')) {
        OSM.Survey.F4.setAnswers('_2');
    }

    OSM.Survey.F4.readOnly(true);
});

Consideraciones:
- Las variables SHELL deben considerarse la fuente primaria de información.
- Las variables derivadas pueden bloquearse mediante readOnly(true) para evitar modificaciones posteriores.
- Este patrón ayuda a garantizar la consistencia entre filtros, cuotas y variables de clasificación.

CASO 6. USO PREFERENTE DE isAnswerSelected() SOBRE indexOf()

Situación:
Cuando se requiera validar si una variable contiene una o varias categorías específicas, se recomienda utilizar isAnswerSelected() como primera opción.

Motivos:
- Proporciona mayor legibilidad.
- Reduce el riesgo de errores de búsqueda.
- Ofrece mejor compatibilidad con preguntas categóricas de respuesta múltiple.
- Facilita el mantenimiento del código.

Ejemplo:

if (s.A2.isAnswerSelected('_20,_21,_22,_23,_24,_25,_26,_27')) {
    OSM.Survey.A2X.setAnswers('_1');

    OSM.Survey.A2X.setAnswers('_2');
} else if (s.A2.isAnswerSelected('_8,_9,_10,_11,_12')) {
    OSM.Survey.A2X.setAnswers('_3');
} else if (s.A2.isAnswerSelected('_13,_14,_15,_16,_17,_18,_19')) {
    OSM.Survey.A2X.setAnswers('_4');
} else if (s.A2.isAnswerSelected('_28,_29,_30,_31,_32,_33,_34,_35,_36,_37,_45,_46')) {
    OSM.Survey.A2X.setAnswers('_5');
} else if (s.A2.isAnswerSelected('_1,_2,_3,_4,_5,_6,_7')) {
    OSM.Survey.A2X.setAnswers('_6');
}

OSM.Survey.A2X.readOnly(true);

Recomendación:
Utilizar indexOf() únicamente cuando exista una necesidad específica que no pueda resolverse mediante los métodos nativos de validación de respuestas.

CASO 8. PROTECCIÓN DEL TEXTO DE ELIMI

Situación:
Cuando la variable o pantalla ELIMI almacena el motivo de terminación de la encuesta, su contenido no debe poder ser modificado por el entrevistador ni por procesos posteriores del flujo.

Implementación:

OSM.Survey.ELIMI.addEventListener('onBeforeNavigateTo', function(e) {
    e.sourceElement.readOnly(true);
});

Consideraciones:
- Aplicar la protección antes de mostrar la pantalla.
- Garantizar la integridad del motivo de terminación registrado.
- Utilizar este patrón especialmente cuando varias reglas de elegibilidad actualicen el contenido de ELIMI durante la entrevista.
