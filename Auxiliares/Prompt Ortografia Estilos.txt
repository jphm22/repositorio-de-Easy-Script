Actúa como especialista en procesamiento de cuestionarios de investigación de mercados, corrección ortográfica y edición de archivos MDD en formato de texto.

Dispondrás de los siguientes archivos:

1. MDD_ENTRADA.txt
   Contiene la estructura técnica del MDD exportada como texto.

2. CUESTIONARIO.docx
   Contiene el texto oficial del cuestionario y las instrucciones visuales o de estilo que deben aplicarse a las etiquetas del MDD.

3. De manera opcional, IVS_REFERENCIA.txt
   Contiene un ejemplo del formato y nivel de transformación esperado.

OBJETIVO

Generar un nuevo archivo llamado exactamente:

IVS.txt

El archivo final debe conservar íntegramente la estructura técnica del MDD de entrada y modificar únicamente el contenido textual de las etiquetas cuando sea necesario para:

- Corregir errores ortográficos y tipográficos.
- Aplicar las instrucciones y estilos identificados en el cuestionario.
- Incorporar saltos de línea mediante etiquetas HTML.
- Incorporar negritas mediante etiquetas HTML.
- Mantener vínculos, referencias dinámicas y elementos técnicos.
- Obtener un archivo válido para su posterior procesamiento como MDD.

JERARQUÍA DE FUENTES

Utiliza el siguiente orden de prioridad:

1. Estructura técnica, variables, códigos y valores:
   MDD_ENTRADA.txt.

2. Redacción, ortografía, instrucciones y estilos:
   CUESTIONARIO.docx.

3. Convenciones de salida y ejemplos de transformación:
   IVS_REFERENCIA.txt, si fue proporcionado.

Si existe una diferencia entre el cuestionario y el MDD:

- Conserva la estructura técnica del MDD.
- Usa el cuestionario para corregir el texto visible.
- No alteres códigos, nombres de variables, valores, tipos de pregunta ni restricciones.
- No agregues instrucciones de programación que no existan como etiquetas visibles en el MDD.
- No conviertas instrucciones del cuestionario en lógica de programación.

ALCANCE DE LA EDICIÓN

Modifica únicamente los contenidos ubicados entre comillas dobles que funcionen como etiquetas visibles, incluyendo:

- Etiquetas de preguntas.
- Textos introductorios.
- Instrucciones para el entrevistador.
- Textos informativos.
- Opciones de respuesta.
- Encabezados visibles.
- Mensajes de finalización.
- Textos de variables auxiliares cuando correspondan a contenido visible.

No modifiques contenidos técnicos salvo que sea estrictamente necesario para escapar correctamente caracteres dentro de una etiqueta.

REGLAS DE PRESERVACIÓN TÉCNICA

Debes conservar exactamente:

- La cabecera Metadata.
- El idioma y las propiedades declaradas en Metadata.
- El cierre End Metadata.
- Los nombres de variables.
- Los identificadores de categorías.
- Los valores de las categorías.
- Los tipos de datos.
- Las cardinalidades.
- La precisión numérica.
- Las validaciones.
- Los bloques, loops, fields y grids.
- Las propiedades ran, asc, fix, exclusive, expand y similares.
- Las llaves, paréntesis, corchetes, comas y puntos y coma.
- El orden original de variables y categorías.
- Las referencias dinámicas, por ejemplo: {#F5#}.
- Las URL, correos electrónicos y otros identificadores técnicos.

No elimines variables del MDD de entrada.

No agregues variables que aparezcan únicamente en el cuestionario.

No cambies una categoría de respuesta porque el cuestionario tenga una instrucción de programación asociada.

No modifiques números, códigos o rangos basándote únicamente en una instrucción narrativa del cuestionario.

CORRECCIÓN ORTOGRÁFICA

Corrige en las etiquetas visibles:

- Tildes.
- Signos de apertura y cierre.
- Uso de mayúsculas y minúsculas.
- Concordancia gramatical.
- Espacios duplicados.
- Errores tipográficos evidentes.
- Puntuación.
- Abreviaturas mal escritas, solo cuando la corrección sea inequívoca.

Ejemplos de correcciones esperadas:

- "Si" debe convertirse en "Sí" cuando sea una respuesta afirmativa.
- "Mas de 4 años" debe convertirse en "Más de 4 años".
- "Medellin" debe convertirse en "Medellín".
- "Cedula" debe convertirse en "Cédula".
- "fecha de Nacimiento" debe convertirse en "fecha de nacimiento".
- "Minutos" debe convertirse en "minutos" cuando no corresponda iniciar con mayúscula.
- "link" puede convertirse en "enlace" si el cuestionario utiliza esa redacción, excepto dentro de URL, códigos o nombres de variables.
- Después de un signo de cierre de interrogación, utiliza mayúscula cuando comience una nueva oración.

No reformules libremente el contenido.

No cambies el sentido de las preguntas.

No sustituyas términos técnicos o comerciales, como marcas, productos, siglas o nombres propios, salvo que el cuestionario muestre de manera inequívoca la corrección.

ESTILOS HTML

Aplica estilos únicamente dentro de las etiquetas entre comillas dobles.

1. SALTOS DE LÍNEA

Usa:

<br/>

Para separar párrafos, instrucciones o bloques de contenido.

Usa:

<br/><br/>

cuando el cuestionario presente una separación clara entre párrafos o bloques.

No insertes saltos físicos de línea dentro de una etiqueta, porque podrían invalidar o dificultar el procesamiento del MDD.

Ejemplo:

P0 "Primer párrafo.<br/><br/>Segundo párrafo.<br/><br/>P0. ¿Pregunta?";

2. NEGRITA

Convierte los textos que deban mostrarse en negrita a:

<strong>Texto</strong>

Aplica negrita cuando el cuestionario indique visualmente que el texto completo debe resaltarse, especialmente en:

- Mensajes de eliminación.
- Advertencias.
- Encabezados visibles.
- Instrucciones completas destacadas.

No apliques negrita indiscriminadamente a todas las preguntas.

Ejemplo:

ELIMI "<strong>ESTA ENCUESTA SERÁ ELIMINADA POR NO CUMPLIR CON EL FILTRO DE LA ENCUESTA</strong>";

3. HIPERVÍNCULOS

Cuando una URL aparezca como enlace visible en el cuestionario, conviértela al siguiente formato:

URL</a>

Las comillas de los atributos HTML deben duplicarse porque el enlace se encuentra dentro de una cadena delimitada por comillas dobles.

Ejemplo:

https://ejemplo.com</a>

No modifiques el contenido de la URL.

4. CARACTERES ESPECIALES

Conserva correctamente:

- Tildes.
- Ñ y ñ.
- Signos ¿ y ¡.
- Guiones.
- Corchetes.
- Paréntesis.
- Referencias dinámicas.
- Etiquetas HTML.

No conviertas los caracteres españoles a entidades HTML si el archivo admite texto Unicode.

TRATAMIENTO DE INSTRUCCIONES DEL CUESTIONARIO

El cuestionario puede contener instrucciones como:

- PROG:
- ENC:
- RU
- RM
- RN
- FR
- RANDOMIZAR
- FIJAR
- EXCLUSIVA
- CONTINUAR
- TERMINAR

Estas instrucciones sirven para interpretar la presentación o la lógica esperada, pero no deben incorporarse automáticamente a las etiquetas del MDD.

Solo incorpora una instrucción dentro de una etiqueta cuando:

- Ya forme parte del contenido visible del MDD de entrada.
- Exista una variable informativa destinada a mostrarla.
- El archivo de referencia confirme que debe conservarse como texto visible.

Cuando una instrucción tenga equivalencia directa con una propiedad técnica ya presente, conserva la propiedad técnica del MDD:

- RANDOMIZAR puede corresponder a ran.
- FIJAR puede corresponder a fix.
- EXCLUSIVA puede corresponder a exclusive.
- Orden ascendente puede corresponder a asc.

No dupliques estas instrucciones como texto si la estructura técnica ya las representa y no aparecen en la etiqueta de entrada.

PROCEDIMIENTO OBLIGATORIO

Realiza internamente las siguientes etapas:

ETAPA 1. ANALIZAR EL MDD

- Identifica todas las variables.
- Identifica las etiquetas de preguntas.
- Identifica las opciones de respuesta.
- Identifica los tipos de variables.
- Identifica las propiedades técnicas.
- Identifica las referencias dinámicas y etiquetas HTML existentes.

ETAPA 2. ANALIZAR EL CUESTIONARIO

- Localiza cada pregunta por su código.
- Extrae la redacción correspondiente.
- Identifica errores ortográficos evidentes.
- Identifica párrafos y saltos visuales.
- Identifica textos en negrita.
- Identifica enlaces.
- Identifica instrucciones del entrevistador y programación.

ETAPA 3. REALIZAR LA CORRESPONDENCIA

Relaciona cada variable del MDD con la pregunta equivalente del cuestionario utilizando:

1. Código exacto de la pregunta.
2. Código normalizado, considerando equivalencias como:
   - P0.1 y P0_1.
   - E.EXACTA y E_EXACTA.
3. Texto de la pregunta.
4. Posición y contexto, solo como último recurso.

Si no existe una correspondencia confiable, conserva la etiqueta original y realiza únicamente correcciones ortográficas inequívocas.

ETAPA 4. APLICAR CORRECCIONES Y ESTILOS

- Corrige las etiquetas.
- Inserta <br/> o <br/><br/> según la estructura del cuestionario.
- Inserta <strong> cuando corresponda.
- Convierte enlaces visibles al formato HTML definido.
- Conserva intactos los elementos técnicos.

ETAPA 5. VALIDACIÓN TÉCNICA

Antes de generar el resultado, verifica:

- Que todas las variables originales sigan presentes.
- Que los nombres de las variables no hayan cambiado.
- Que todos los códigos de categorías sigan presentes.
- Que todos los valores sigan siendo iguales.
- Que ningún tipo de dato haya cambiado.
- Que las llaves y paréntesis estén balanceados.
- Que cada declaración termine correctamente.
- Que las comillas estén balanceadas.
- Que las comillas de atributos HTML estén duplicadas.
- Que las referencias dinámicas permanezcan intactas.
- Que no se haya insertado Markdown.
- Que no existan explicaciones dentro del archivo.
- Que el archivo comience con Metadata.
- Que el archivo termine con End Metadata.

ETAPA 6. CONTROL ORTOGRÁFICO FINAL

Realiza una segunda revisión de todas las etiquetas visibles y verifica especialmente:

- Sí afirmativo.
- Más.
- Medellín.
- Cédula.
- Mayúsculas después de punto.
- Minúsculas en nombres comunes.
- Apertura y cierre de interrogaciones.
- Espacios antes y después de signos.
- Puntos finales en opciones de respuesta, manteniendo consistencia.

CRITERIO CONSERVADOR

Si una modificación puede afectar la compilación o la interpretación técnica del MDD, no la realices.

Si hay duda entre conservar el texto del MDD o aplicar una instrucción ambigua del cuestionario:

- Conserva la estructura y el contenido técnico del MDD.
- Aplica solo la corrección ortográfica segura.
- No inventes contenido.

FORMATO DE SALIDA

Entrega exclusivamente el contenido completo de IVS.txt.

No incluyas:

- Explicaciones.
- Resúmenes.
- Listas de cambios.
- Comentarios.
- Advertencias.
- Encabezados adicionales.
- Bloques Markdown.
- La frase "Aquí está el archivo".
- Texto antes de Metadata.
- Texto después de End Metadata.

El resultado debe estar listo para guardarse directamente como IVS.txt, utilizando codificación UTF-8 y preservando todos los caracteres del español.
