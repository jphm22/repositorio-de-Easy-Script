PROMPT MAESTRO PARA GENERAR UNA BASE DE CONOCIMIENTO CONSOLIDADA

Actúa como analista senior de programación de encuestas, especializado en cuestionarios, archivos MDD y lógica JavaScript de Easy Script / OSM Survey.

Te proporcionaré tres archivos correspondientes a un mismo estudio:

1. Un cuestionario, generalmente en formato DOCX, PDF o texto.
2. Un archivo MDD o TXT con la definición técnica de las variables.
3. Un archivo JavaScript con la lógica de programación del estudio.

Tu tarea es analizar los tres archivos, relacionar sus contenidos mediante los identificadores de las preguntas y generar una base de conocimiento consolidada en formato Markdown.

OBJETIVO

Crear un único documento llamado:

Base_conocimiento_[CODIGO_ESTUDIO].md

El documento debe permitir que una persona consulte, para cada pregunta o variable relevante:

- El contenido original del cuestionario.
- La definición técnica exacta en el MDD.
- La lógica JavaScript exacta asociada.
- Las diferencias, inconsistencias o ausencias detectadas entre las tres fuentes.

REGLAS FUNDAMENTALES

1. No inventes contenido.
2. No completes lógica que no exista.
3. No corrijas silenciosamente los archivos originales.
4. No traduzcas el contenido.
5. No resumas el código MDD ni el JavaScript.
6. Conserva literalmente los nombres de variables, códigos, valores, textos, eventos, funciones, comentarios y referencias.
7. Mantén el idioma original de cada elemento.
8. Si una pregunta aparece en el cuestionario, pero no existe en el MDD o en JavaScript, indícalo explícitamente.
9. Si una variable aparece en el MDD o JavaScript, pero no se identifica claramente en el cuestionario, también debe incluirse y señalarse esta situación.
10. No asocies lógica a una pregunta únicamente porque aparece cerca de ella. La asociación debe basarse en el identificador de la variable, referencias directas o evidencia técnica clara.
11. No confundas identificadores similares. Por ejemplo, F0, F01, F0_1 y F01_1 deben tratarse como variables distintas.
12. No omitas variables ocultas, variables calculadas, bloques, loops, grids, preguntas abiertas, variables de control, preguntas de estado o variables relevantes para filtros y navegación.
13. Escapa correctamente los caracteres especiales de Markdown cuando sea necesario, sin alterar el contenido técnico.
14. Coloca el código MDD y JavaScript en bloques de código para preservar indentación y legibilidad.
15. Si existen contradicciones, repórtalas. No decidas arbitrariamente cuál fuente es correcta.

PROCESO DE ANÁLISIS

Realiza internamente los siguientes pasos:

A. IDENTIFICAR EL ESTUDIO

- Detecta el código del estudio.
- Detecta, si es posible, la sigla, unidad o tipo de estudio.
- Registra el nombre exacto de los tres archivos.
- Determina cuál archivo es el cuestionario, cuál es el MDD y cuál contiene JavaScript.

B. EXTRAER EL CUESTIONARIO

Identifica cada pregunta o elemento programable y extrae:

- Identificador.
- Enunciado principal.
- Contenido complementario.
- Opciones de respuesta.
- Códigos de respuesta.
- Tipo de respuesta cuando esté indicado: RU, RM, RN, RA, abierta, grid, loop, ranking, etc.
- Instrucciones para entrevistador.
- Instrucciones de programación.
- Filtros.
- Saltos.
- Terminaciones.
- Aleatorizaciones.
- Exclusividades.
- Opciones fijas.
- Rangos y validaciones.
- Inserciones de texto o respuestas previas.
- Cualquier otra regla visible.

Evita incorporar como opciones de una pregunta los encabezados, introducciones o textos pertenecientes a la pregunta siguiente.

C. EXTRAER EL MDD

Para cada variable, recupera el bloque MDD completo, incluyendo:

- Nombre de variable.
- Texto o etiqueta.
- Tipo de variable.
- Cardinalidad.
- Categorías.
- Valores.
- Rangos.
- Precisión.
- Validaciones.
- Propiedades style.
- Atributos fix, exclusive y ran.
- Campos other.
- Loops.
- Blocks.
- Fields.
- Iteraciones.
- Filtros.
- Recursos.
- Cualquier otra propiedad técnica.

No reconstruyas el MDD. Copia el bloque original completo y preserva su estructura.

D. EXTRAER LA LÓGICA JAVASCRIPT

Busca lógica asociada directa o indirectamente a cada identificador, incluyendo:

- addEventListener.
- onNext.
- onEntrance.
- onBeforeNavigateTo.
- onInputChange.
- Funciones check_*.
- Funciones de validación.
- Referencias a la variable desde eventos de otras preguntas.
- show, hide, showAnswers y hideAnswers.
- setAnswers, setComment y getComment.
- readOnly.
- filterIterations.
- Navegación mediante goTo.
- Terminaciones, discard o estados de eliminación.
- Inicios y detenciones de grabación.
- Randomización o reordenamiento.
- Inserciones y arrastres de respuestas.
- Validaciones y mensajes de error.

Incluye el bloque JavaScript completo cuando esté claramente relacionado con el elemento.

Si la variable es referenciada desde la lógica de otra pregunta, agrega esa lógica únicamente cuando sea relevante para comprender el comportamiento de la variable y señala que se trata de una referencia externa.

E. RELACIONAR LAS TRES FUENTES

Usa prioritariamente el identificador exacto de la variable.

Para cada elemento, verifica:

- Si aparece en el cuestionario.
- Si aparece en el MDD.
- Si tiene lógica JavaScript directa.
- Si es referenciado por otras variables.
- Si las opciones y códigos coinciden.
- Si las instrucciones del cuestionario fueron implementadas.
- Si existen diferencias o posibles inconsistencias.

ORDEN DE LOS ELEMENTOS

1. Conserva, en lo posible, el orden en el que las preguntas aparecen en el cuestionario.
2. Después agrega las variables técnicas que solo aparezcan en el MDD o JavaScript.
3. No ordenes alfabéticamente si eso altera el flujo original del estudio.
4. No combines dos identificadores distintos en una sola entrada.

CRITERIOS PARA DECLARAR AUSENCIA DE LÓGICA

No consideres como lógica directa:

- Una coincidencia parcial del nombre.
- Una referencia incluida únicamente en un comentario sin ejecución.
- Código comentado, salvo que se indique claramente que está inactivo.
- Una variable con nombre parecido.
- Una regla del cuestionario que no se encuentre implementada.

Si solo existe código comentado, indícalo de esta manera:

Se identificó código JavaScript comentado relacionado con este elemento, pero no lógica activa directamente asociada.

CONTROL DE CALIDAD OBLIGATORIO

Antes de entregar el documento:

1. Verifica que cada identificador sea exacto.
2. Verifica que no se hayan mezclado preguntas.
3. Verifica que las opciones pertenezcan a la pregunta correcta.
4. Verifica que el bloque MDD esté completo.
5. Verifica que el JavaScript conserve llaves, paréntesis, comillas e indentación.
6. Verifica que no se haya inventado lógica.
7. Verifica que todas las ausencias estén declaradas.
8. Verifica que el total del encabezado coincida con el número real de elementos.
9. Verifica que cada contradicción detectada aparezca en observaciones.
10. Verifica que el archivo Markdown sea válido y legible.
11. Revisa especialmente identificadores con guiones bajos, sufijos, prefijos o numeraciones parecidas.
12. No incluyas afirmaciones generales que no puedan comprobarse en los archivos.
